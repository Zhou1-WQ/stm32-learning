
# 3-4按键控制 LED

## 这次做了什么

点灯和读按键各封装成驱动文件，main 只调度：按一下键，LED 翻转一次。

## 工程结构

```
User/main.c        主逻辑（只有调度）
Hardware/LED.c/h   LED 驱动
Hardware/Key.c/h   按键驱动
```


## 按键消抖

```c
if (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_1) == 0)   /* 按下=低电平 */
{
    Delay_ms(20);                                          /* 消抖 */
    while (GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_1) == 0); /* 等松手 */
    Delay_ms(20);
    return 1;
}
```

- 按下先等 20ms：跳过机械抖动
- `while(...==0);` 空语句卡住：**松手才返回**，一次按下只算一次
- 按键初始化用 `GPIO_Mode_IPU`（上拉输入）

## main 只写业务

```c
LED_Init();
Key_Init();

while (1)
{
    KeyNum = Key_GetNum();
    if (KeyNum == 1) LED_Turn();
}
```

`LED1_Turn()` 内部用 `GPIO_ReadOutputDataBit` 读 ODR 再取反——**读的是输出状态，不是输入**。

## 现象

- 按一下 LED 亮灭翻转一次

## 踩坑

**坑 1：按住不放，LED 一直闪**

- 现象：按住不放，LED 一直快速闪
- 原因：`while (...);` 漏了 `== 0`，条件变成"按下时成立"，按下就立刻退出，主循环反复返回 1 反复翻转
- 正确：`while (... == 0);` —— 按着不走，松手才走

**坑 2：按没反应，拔插线才有反应**

- 现象：手按按键 LED 不变，把线拔下来再插上 LED 反而变了
- 原因：线插在**绕过按键**的位置（直接接到电源脚或相邻不导通的列），此时 B1 的电平变化由"线"决定，跟按键无关
- 排查顺序：
  1. 看线的板子端是不是插在 **GPIO 引脚**（B1）而不是底部 `G`/`3.3` 电源脚
  2. 看线的按键端是不是和按键脚**同一列**（面包板每列 5 孔纵向互通，插隔壁列等于没接）
  3. 轻拔线头，拔不动才算插到底（虚接会导致"摇一摇才变"）
- 判定：接对后**手完全不碰线**，只按键 → LED 翻转

**坑 3：四脚按键必须跨"异侧"取电**

- 四脚按键内部①—②、③—④两两常通，只有跨左右两侧才由按键控制通断
- 接成同侧（③和④）→ 永远通，按下也不变，等于短路
- 记住：**同侧同组，异侧才开**；四个脚都插进面包板是机械固定，但只需要接对角两个


## 为什么要模块化

| 好处 | 体现 |
|---|---|
| 换引脚只改一处 | PA1 换 PB0 只动 LED.c |
| main 只写业务 | main 里没有寄存器操作 |
| 团队协作 | 接口在 .h 说清楚，各写各的 .c |

这就是驱动层 + 应用层的雏形，VCU/BMS 代码都这么组织。
