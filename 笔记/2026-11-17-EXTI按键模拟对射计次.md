# 5-2 用按键 + EXTI 模拟对射式红外传感器计次

## 这次做了什么

用**按键**接在传感器原来的位置（PB1 + EXTI1）。按一下键 = 传感器被遮挡一次 = **LED 翻转一次**代表计了一次。

本质：两者都是"信号来一个下降沿 → 记一次"。传感器是遮挡输出低电平，按键是按下接地低电平，对 STM32 来说完全一样。

| | 对射传感器 | 按键替代 |
|---|---|---|
| 接在哪 | PB1 | PB1（同一引脚） |
| 信号来源 | 遮挡 → 输出低电平 | 按下 → 接地低电平 |
| STM32 看到的 | 下降沿 | 下降沿 |
| 记一次 | 遮挡一次 | 按一下 |

## 接线

按键一脚接 PB1，另一脚接 GND。GPIO 配 `GPIO_Mode_IPU`（上拉输入）。

- 没按下 = 高电平，按下 = 低电平，松手回到高电平
- 下降沿触发 → **按下那一刻**记一次

## 代码

核心就一个中断函数——每次下降沿，翻一次灯，清标志：

```c
void EXTI1_IRQHandler(void)
{
    if (EXTI_GetITStatus(EXTI_Line1) == SET)
    {
        LED_Turn();                            /* 记一次 → 灯翻转 */
        EXTI_ClearITPendingBit(EXTI_Line1);    /* 必须清标志 */
    }
}
```

## 踩坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 按一次亮，第二次起就不对 | `LED_Init()` 写在中断里，每次进中断都把灯复位成初始态 | 初始化只放 main 开头，中断里只翻转 |
| 按键没反应 | 触发方式选了双边沿 `Rising_Falling`，按下+松开翻两下 = 没翻 | 只用单边沿：下降沿（按下触发）、上升沿（松开触发）都行 |
| 想在中断里 `Delay_ms(20)` 消抖，程序直接卡死 | Delay 靠 SysTick 中断推进计数；进了 EXTI 中断后 SysTick 被挡在外面，计数不走 → while 死循环 | 中断里绝不延时；要消抖就中断里置标志，main 里判断 |
| 抢占和响应都填 1，为什么 | 分组 2 拆成抢占 2 位 + 响应 2 位，各能填 0~3；现在只有一个中断，填几都一样 | 照抄 1；把 0 留空给以后更急的中断（CAN、BSPD） |
| 中断函数不执行 | 函数名和启动文件向量表对不上 | 逐字核对 `EXTI1_IRQHandler` |

**最重要一条**：初始化 = 上电做一次（放 main）；中断 = 事件来了做一次，只干最小的活（判断标志 → 翻转 → 清标志）。

<details>
<summary>备查：为什么中断里不能延时</summary>

SysTick 和 EXTI 同级时，CPU 正在跑 EXTI 中断，SysTick 中断进不来 → `Delay_ms()` 里等 SysTick 更新计数的 while 永远等不到 → 死循环卡死。

就算用空 `for` 循环硬等，也会把中断拖得很长，主程序被卡住。消抖的正确做法：中断里只置 `Key_Flag = 1`，main 里检测到标志后延时判断、清标志。

</details>
