## 二、ST-Link 接线（今天最大的坑）

ST-Link V2 的引出端是**2×5 双排公针 + 防呆护套**，单排 4 孔母座插不进去——护套壁和邻排针会把壳体卡住。**必须把 4 孔连体壳拆成单根母头**，一根一根插。

| 线色 | 板子端丝印 | ST-Link 针号 |
|---|---|---|
| 棕 | `3V3` | ⑦ 或 ⑧（3.3V） |
| 红 | `SWD` | ④（SWDIO） |
| 橙 | `SWCLK` | ②（SWCLK） |
| 黄 | `GND` | ⑤ 或 ⑥（GND） |

**踩坑记录：**

1. 配色搞反了——常规是「红=VCC、黑/棕=GND」，我这边是「黄=GND、棕=3.3V」。功能上能通，但**回头看线时极易误判**，红当电源往 3.3V 上一插就是短路烧板。以后统一按常规配色。
2. ST-Link 的 2×5 座，**每个位置有上下两个孔**：上排奇数 ①③⑤⑦⑨（RST/SWIM/GND/3.3V/5.0V），下排偶数 ②④⑥⑧⑩（SWCLK/SWDIO/GND/3.3V/5.0V）。插错排在位置 3、4 上没影响（两排都是 GND 和 3.3V），只有位置 1、2 决定成败。
3. `⑨⑩ 是 5.0V，绝对不能接`。⑤⑥ 才是 GND，别数错。

## 四、第一个程序

`User/main.c`：开 GPIOC 时钟 → PC13 推挽输出 → 循环翻转。

板上自带 LED 挂在 **PC13**，低电平点亮，所以 `GPIO_ResetBits` = 亮，`GPIO_SetBits` = 灭。不用外接任何线。

编译结果：`0 Error(s)`，一条 warning：

```
main.c(11): warning: #1-D: last line of file ends without a newline
```

C 标准要求源文件以换行结束。处理办法：文件末尾敲一个回车。**每个源文件结尾留个空行**，这个警告就再也不出现。

## 五之二、灯亮但不闪的坑

第一次看到的是「绿灯常亮，不闪」。原因不是程序没跑，而是**延时太短**：

`Delay(500000)` 在 72MHz 下只有 30–50ms，一亮一灭约 10–16Hz。**超过每秒 10 次的变化，人眼会融合成持续点亮**（视觉暂留，和电影每秒 24 帧同一个原理）。所以看到的是"亮着但有点暗"的常亮。

解决：延时从 `500000` 放大到 `5000000`。

> 这条经验值得单独记住：**"灯常亮"和"灯闪太快"肉眼几乎无法区分，但原因完全不同。** 调试时永远先怀疑"太快看不见"，而不是"程序没跑"——判断方法是把延时放大 10 倍看是否出现变化。

顺带认识到 `while(t--)` 这种空循环延时的缺陷：**长短完全取决于编译器优化等级**，换个工程/换 O1 O2 优化就不准了。后面定时器章节要用 SysTick 做精确毫秒延时。

## 五之三、新建工程漏配 Define 的教训

第二次独立新建工程时，编译直接爆红：

```
error: use of undeclared identifier 'RCC_APB2Periph_GPIOC'
```

原因：**魔棒 → C/C++ → Define 框没填**。这个框是空的时候，`stm32f10x.h` 不会去加载外设库头文件，所有 `RCC_xxx`、`GPIO_xxx` 全都不认识。

必填内容：

```
USE_STDPERIPH_DRIVER,STM32F10X_MD
```

同时 Include Paths 要加 `..\Start`、`..\Library`、`..\User` 三个路径。

这个报错的辨识度极高，以后见到直接去查 Define。完整流程见 → [Keil新建工程完整步骤.md](./Keil新建工程完整步骤.md)
